# Golden vectors

Each `*.json` file here is a list of input/output cases that the Rust crate, the Python bindings and the WebAssembly bindings must all reproduce. The format is `golden-vectors@1` from [evidence-kernel](https://github.com/chethandvg/evidence-kernel).

The vectors are generated by [`generate.py`](generate.py), the reference (oracle) implementation. It uses exact rational arithmetic wherever the result is rational. Regenerate with:

```bash
python vectors/generate.py
```

| File | Functions |
|---|---|
| [`equal_temperament.json`](equal_temperament.json) | `midi_to_hz`, `midi_to_hz_with_reference`, `hz_to_midi` |
| [`intervals.json`](intervals.json) | `cents` |
| [`notes.json`](notes.json) | `note_name`, `nearest_note` |
| [`octaves.json`](octaves.json) | `octave_transpose`, `octave_fold` (zero tolerance) |
| [`harmonics.json`](harmonics.json) | `harmonic`, `is_octave_harmonic` (zero tolerance) |
| [`rhythms.json`](rhythms.json) | 10-minute and 24-hour rhythms raised into the audible range |
| [`errors.json`](errors.json) | invalid input, in every function |

Every case names the claim in [`claims.yaml`](../claims.yaml) that it tests. The oracle mirrors `midi_to_hz`, `hz_to_note` and `octave_transpose` of the earlier `lifesound.py` toolkit. Two deliberate differences: `nearest_note` returns fractional cents (the old `hz_to_note` rounded to whole cents), and exact halves always round up, so the offset is in [-50, 50) cents.
